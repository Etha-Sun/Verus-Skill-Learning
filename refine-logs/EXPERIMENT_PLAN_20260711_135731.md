# Corrected Information-Gain Experiment Plan

**问题**：如何判断 trajectory-conditioned skill/rationale 是否真正帮助 VeruSAGE repair，而不是仅由 prompt formatting、长度或 tokenization 产生虚假 IG？

**方法主张**：在 action、proof patch 和 full verified proof 三个层级做 paired conditional scoring；以 matched controls 验证信息特异性，以 artifact-token information density 衡量效率，以 verifier live metrics 验证最终价值。

**日期**：2026-07-11

## Claim Map

| Claim | 最小可信证据 | Blocks |
|---|---|---|
| C1 artifact-specific utility | relevant artifact 在 paired state 上稳定超过 shuffled、wrong-error、length-matched neutral controls | B1-B3 |
| C2 token-efficient utility | positive PMI 同时具有更高 `sum(PMI_bits)/sum(artifact_tokens)`，并存在可解释的 utility-cost frontier | B2-B4 |

Anti-claims：结果不能由 action serialization、chat formatting、artifact header、文本长度、同题泄漏或 final-proof leakage 解释。

## B1 Measurement Calibration（MUST）

- 修复 joint context-target tokenization；corrected action run 使用 chat generation boundary。
- 构造 deterministic candidate action set，评分每个 option，softmax 得到归一化 action distribution。
- 保存每个 option 的 raw score、normalized probability、correct-action PMI bits、entropy change。
- 单元测试覆盖 token boundary、probability sum、baseline cache identity、bits/nats conversion。
- Gate：首 token 不再出现由 boundary 导致的异常；candidate probabilities 和为 1；相同 baseline 完全一致。

## B2 Matched-Control Action IG（MUST）

- 数据：旧 sanity manifest 的 3 verified traces / 7 states。
- Artifact：generic、state-conditioned rationale、shuffled rationale、wrong-error rationale、length-matched neutral、weak irrelevant、empty container。
- Target：successful trace 的 demonstrator action，不称为唯一 optimal action。
- 指标：PMI bits、correct-action probability delta、top-1/rank、entropy delta、paired win rate、artifact tokens、global information density。
- Gate：state-conditioned artifact 对 shuffled/wrong control 至少显示方向性 separation；否则先改 artifact generation，不扩大数据。

## B3 Patch And Full-Proof IG（MUST，B1 通过后）

- Patch：确定性 proof-relevant diff，保留 retained/dropped hunk audit。
- Full proof：能放入窗口时做 exact teacher forcing；超长时分别报告 first-K、rolling-window 和 anchored-chunk，后两者标为 approximate。
- 指标：IG sum、target-token mean、artifact-token density、chunk/hunk distribution、paired control separation。
- Gate：至少一个 long target 对 relevant vs matched control 有稳定 separation，且结果不是单个 chunk/outlier 驱动。

## B4 Utility-Cost And Visualization（MUST）

- 扫 artifact token budget 或 retrieved top-k。
- 图：三 target heatmap、paired distribution、utility-cost frontier、PMI-entropy quadrant、trajectory timeline、full-proof chunk heatmap。
- 不跨 target 直接比较未标准化 raw IG；同时报告 bits、effect size 和 rank。

## B5 Scale And Live Validation（CONDITIONAL）

- 只有 B1-B3 通过后扩大到 20-50 traces。
- 按 normalized task id 分组；train 生成/挖掘、dev 定阈值、held-out test 一次评估。
- 最终 metrics：verifier solved rate、总 tokens、attempts、repetition、wall time。

## Stop Conditions

- scorer invariant 失败：停止 GPU run，修复实现。
- matched controls 与 relevant artifact 不可区分：停止扩大，改 artifact generation。
- full proof 超窗且近似协议对 chunking 高敏感：保留为不确定结果，不包装成 exact probability。
- offline IG 不预测 small live rerun：IG 只能作为诊断，不能作为 skill promotion 主指标。
