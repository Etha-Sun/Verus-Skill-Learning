# Experiment Plan: V-FACE Phase 0–1

**Problem**: SkillOpt 的 whole-skill outcome 无法区分 formal action validity、card exposure effect、adoption 与 invalid infrastructure。
**Method thesis**: Build-only typed executable evidence 是否能跨 checkpoint 改善 proof-card exposure admission。
**Date**: 2026-08-21
**Current scope**: compiler feasibility + prospective admission pilot；不含 final sealed performance claim。

## Claim Map

| Claim | Why it matters | Minimum convincing evidence | Blocks |
|---|---|---|---|
| G0 feasibility gate | 没有可靠 instantiation，后续 credit/retrieval 都无意义 | 30 checkpoints 上 ≥18 instantiable；其中 ≥90% semantically correct、100% Lynette fidelity、越界≤5% | B0–B1 |
| C1 prospective admission | typed forced/exposure Build evidence 比 observational/generic replay 更安全地预测 unseen exposure sign | evaluable-pair coverage ≥40%；等 actor/API budget 下 false admission 更低且 harm recall 不降；优于 forced-only/exposure-only | B2–B3 |
| C2 failure taxonomy | forced validity 与 exposure outcome 的不一致是稳定 formal-skill failure mode | 跨 declaration 重复出现至少两类 disagreement，且 adoption audit 可复现 | B3 |

**Anti-claim**: 收益不能仅来自 atomicization、abstention、更多 replay、更多 tokens 或 test-set tuning。

## Experiment Blocks

### B0 — Inventory and Contamination Audit

- **Claim tested**: 有足够多、无污染、跨 declaration 的 candidate checkpoints 支撑 Phase 0/1。
- **Setup**: 只读取 metadata/source hashes 与 declaration/lemma signatures；不打开 Evaluation trajectories。
- **Outputs**: candidate ledger、duplicate components、eligible counts per patch family、proposed Build/Evaluation manifest hashes。
- **Gate**: 至少能提供 30 Build compiler checkpoints；若 prospective benchmark需要的每-template support 不足，停止 C1，只做 compiler/audit。
- **Cost**: CPU-only；MUST-RUN。

### B1 — Typed Compiler Feasibility

- **Claim tested**: 三类 `CardTemplate` 能稳定产生局部、合法、fidelity-preserving 的 `CardInstantiation`。
- **Dataset**: 30 blinded Build checkpoints；三类 family 每类尽量≥5，跨≥10 declarations。
- **Procedure**: 两名标注者独立标 family/roles/allowed range；冻结 compiler 后实例化；运行 identity/mismatch controls、Verus 与 Lynette。
- **Metrics**: instantiation rate、semantic correctness agreement、Lynette fidelity、out-of-region rate、forced verifier delta、compiler error taxonomy。
- **Success gate**: ≥18/30 instantiable；其间 ≥90% blind semantic correctness；100% Lynette fidelity；越界/无关≤5%；controls 不系统改善。
- **Failure interpretation**: 任何关键 gate 未过就停止 optimizer/retrieval/admission；转成 extractor failure benchmark。
- **Cost**: CPU-only，1–2 days；MUST-RUN；Table 1/appendix audit target。

### B2 — Exposure Label Stability Dry Run

- **Claim tested**: 3+3 independent replicates 能产生足够稳定的 BENEFICIAL/HARMFUL/INCONCLUSIVE label。
- **Dataset**: 6–10 Build tasks，非 Evaluation；只用通过 B1 的 templates。
- **Conditions**: core vs core+one card；condition order randomized；固定 actor/model/tool/budget/card-token envelope。
- **Metrics**: label repeatability under resampling、inconclusive fraction、fidelity-invalid repeatability、run variance、cost。
- **Gate**: 至少 60% pairs 在预注册 label rule 下 conclusive，且重新抽取 2-of-3 replicate 子集时标签一致率≥80%；否则增加 replicate 是唯一允许的 protocol revision，且必须重新核算预算。
- **Cost**: ≤2 GPUh/API-equivalent actor time；MUST-RUN only after B1。

### B3 — Prospective Admission Pilot

- **Claim tested**: V-FACE admission 超过 strongest budget-matched baseline。
- **Dataset**: frozen Evaluation checkpoint–template pairs；所有 decisions 在 exposure rollout 前提交并 hash。
- **Systems**: whole-skill outcome、atomic observational、CAR-like replay、TRACE-like attribution、forced-only、exposure-only、V-FACE。
- **Budget matching**: identical actor rollout/request/token envelope；单列 verifier invocations/CPU seconds/wall time。
- **Primary metrics**: HARMFUL recall、false admission、balanced accuracy on conclusive evaluable pairs、decisive coverage。
- **Secondary**: retained-success regression、valid success、cost ROPE、adoption telemetry、resource cost/correct decision。
- **Success gate**: coverage≥40%；相对 strongest baseline false admission下降、harm recall不降；不是 forced-only/exposure-only 可解释；clustered interval 不与明显反方向结果兼容。
- **Failure interpretation**: coverage fail → non-deployable；no baseline advantage → negative audit；只有 disagreement taxonomy稳定 → benchmark-only contribution。
- **Cost**: bounded remainder ≤6 GPUh/API-equivalent；MUST-RUN only after B2。

### B4 — New Sealed End-Task Evaluation

- **Status**: CUT from current run；future, separately preregistered。
- **Reason**: 现有 test 已被查看，且 C1 未通过前跑 final end-task set 会浪费预算并制造选择压力。
- **Future systems**: core、monolithic SkillOpt、atomic observational、V-FACE top-one exposure；至少两个 actors、多 replicates。
- **Primary endpoints**: Verus+Lynette valid success、retained-success regression、harmful exposure、valid-run resource cost。

## Baseline Protocol Details

- **Atomic observational**: 只统计 Build trajectory 中 adoption-signature 与 outcome 的相关差异，不做新 replay。
- **CAR-like**: 在相同 actor envelope 内，对首次 adoption-signature decision 做 resample/replace 并向后 rollout；只用 task outcome，不见 typed forced delta。
- **TRACE-like**: 给相同局部 windows 与 verifier/tool-call envelope，让 attribution model输出 create/update/reject；不给 executable typed edit。
- **Forced-only / Exposure-only**: 使用与 V-FACE 相同 support/harm rule，只移除另一类 evidence，隔离组合必要性。

## Main Risks

- **Compiler support too sparse**: stop at B1；不要用更多自由文本 patch 掩盖。
- **Evaluation pool too small/contaminated**: 不做 C1 claim；改做 checkpoint audit。
- **All UNKNOWN**: coverage<40% 自动失败，不调松 threshold。
- **Generic replay matches V-FACE**: 接受 negative result；typed evidence不构成方法新意。
- **Actor variance dominates**: B2 决定 replicate count；不在 test 上补救。
