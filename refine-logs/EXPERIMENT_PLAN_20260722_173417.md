# R041A 与 ATLAS 大小模型配对实验计划

**日期**：2026-07-22
**阶段**：mechanism / diagnostic pilot；不打开 sealed MA/NR test，不支持 solved-rate 主张。

## 1. 问题与冻结主张

**C1（R041A，定性机制）**：同一个 632-token、由独立成功 traces 蒸馏的全局 H2 prompt，是否会相对 H0 和等长、trace-free 的 H1 改变 Qwen3.6-27B 在三种预先冻结行为案例上的结果与失败模式。

**C2（ATLAS，诊断能力层级）**：在相同的冻结 ATLAS taxonomy、8 条 held-out FAILED/TIMEOUT traces、可见 classifier prompt 与输出 schema 下，Qwen3.6-27B 和 gpt-5.6-sol/high 是否呈现稳定、可证据定位的 failure diagnosis 差异。

边界：C1 不是 held-out method-effect 或 solved-rate 证据；C2 是 operational model comparison，不是纯参数规模因果，因为本地 OpenAI-compatible 与 Codex CLI 的 transport、隐藏系统指令和 token accounting 不同。大模型不是 gold label；self-reported confidence 不是 accuracy。

## 2. 冻结对象

### R041A cases

只使用 H0 repetitions 选择，且在查看任何 H1/H2 outcome 前冻结：

| Case | Rank / calibration id | H0 labels | 选择理由 |
|---|---|---|---|
| `stable_pass` | 5 / `5372cee76ecb03502a30` | pass / pass / pass | 严格 3/3 security-valid pass |
| `stable_closest_failure` | 22 / `099e5503300d7b344c40` | closest / closest / closest | 严格 3/3 localized single proof failure |
| `unstable` | 21 / `08a957ddd7a2bc344621` | stalled / pass / pass | 三次均有结果且无 infra/unsafe，结果发生变化 |

`unstable` 是 consistency case，不等同于“完全没思路”；其 stalled repetition 的具体失败机制须在分析中单独说明。

### ATLAS paired set

- 复用既有 28-code canonical taxonomy，不重新 induction。
- 使用 reserved eval 中全部 8 条 FAILED/TIMEOUT traces：4 FAILED + 4 TIMEOUT；每个原始 generator 各贡献一条 FAILED 和一条 TIMEOUT；与 40 条 taxonomy-train tasks 的 normalized task overlap 为 0。
- 模型：local `qwen35-27b` 与 frontier `gpt-5.6-sol/high`。
- 第一阶段每模型每 trace 1 次，共 16 calls；这是配对 qualitative pilot。只有发现明显 stochastic/format instability 时，才预注册后续 repetitions，不能事后只重跑不利样例。

## 3. 实验 blocks（按 gate 执行）

### B1 — Freeze 与实现完整性（MUST）

- 产出不可覆盖的 R041A case/job manifest：3 cases × H0/H1/H2 × 3 repetitions = 27 records；9 个 H0 仅引用既有结果，新增 18 个 H1/H2 runs。
- 产出不可覆盖的 ATLAS pair manifest：taxonomy/input SHA-256、精确 8-task 顺序、模型/transport/version/config。
- 测试 overwrite refusal、hash mismatch、case contract、exact paired trace IDs、resume 和 per-call logging。
- Gate：所有 hashes/IDs/schema 固定且测试通过；否则不启动 live run。

### B2 — ATLAS paired classification（MUST）

- Qwen 与 frontier 使用同一 taxonomy、trace adapter、可见 system/user prompt 和 JSON diagnosis schema。
- Qwen 走本地 OpenAI-compatible endpoint，temperature=0、thinking disabled；frontier 走 Codex CLI high。逐 call 保存 prompt/response hash、wall time、transport 和可得 usage。
- 先跑各模型一条 sanity；配置未改变时计入正式 8 条。
- Gate：每模型 8/8 schema-valid、taxonomy-code-valid diagnosis；否则先归类 format/transport failure，不把它解释为诊断能力。

### B3 — R041A live contrast（MUST）

- 共享本地 vLLM 的任务严格串行，避免 ATLAS Qwen 与 R041A 同时竞争 GPU、污染 wall time。
- H1/H2 run 顺序按 case/condition/repetition 冻结并交错；相同 Qwen/Copilot/Verus/Lynette/budget/source/prompt identities。
- H1/H2 的静态长度 gate 使用冻结 Qwen tokenizer 计数（633 vs 632，差 0.16%）。首对完成后检查 provider usage 是否可得；Copilot 只报告受后续轨迹影响的 whole-session input total，不把这个 post-treatment 总量误当作 initial-prompt 长度 gate。若未来能取得 provider first-request tokens，再额外报告而不改变本轮选择。
- Gate：新增 18/18 records 完整，并能与 9 个冻结 H0 records 对齐；缺结果只报告 incomplete。

### B4 — Failure-mode analysis（MUST）

- R041A：case-level pass transition、unsafe/infra、Verus error family、edit/tool behavior、tokens/time；不汇总成泛化 solve-rate claim。
- ATLAS：coverage、code/category agreement、evidence 是否能在 trace 中定位、recovery hint 的具体性；按 FAILED/TIMEOUT、project、原 generator 分层。confidence 仅描述。
- 大小模型差异至少需在两条 traces、跨两个 strata 重现且证据审计方向一致，才称 `repeated takeaway`；单条为 anecdote。

### B5 — 决策（MUST）

- 若 ATLAS 只显示 transport/format instability 或差异小于模型自身不稳定性：结论为暂无稳定 scale takeaway；不做 taxonomy induction。
- 若配对诊断显示重复且 grounded 的差异：再设计 3-repetition robustness 或小模型 taxonomy induction，作为新 run block。
- R042 frontier held-out baseline 继续保持独立，不能用本轮 qualitative results 解锁 confirmatory claims。

## 4. 调度与资源

1. 先冻结 manifests 并运行 model-free tests。
2. frontier ATLAS 在 Codex CLI 后台启动，可与本地任务并行。
3. 本地 Qwen ATLAS 8 calls 完成后，立即接续 R041A 18 个 H1/H2 runs；二者不并发占用同一 vLLM。
4. 每个长任务使用 screen、唯一 run directory、逐项状态文件；已有 Qwen service 只复用，不重启。

预计：ATLAS Qwen 约 0.5–1.5 小时；frontier ATLAS 约 0.5–2 小时；R041A 18 runs 依既有每题 timeout 上界可能需要数小时。最终以实时日志和完成计数更新，不用静态估时替代状态。

## 5. 成功标准与预期 artifacts

- 计划级成功：B1 contracts 和 tests 全部通过。
- 运行级成功：ATLAS 16/16 paired calls 与 R041A 新增 18/18 runs 都有完整 provenance；运行失败也必须有明确 failure class。
- 分析级成功：产出逐 trace/case 的可核查对照，明确 `repeated`、`suggestive`、`anecdotal` 或 `no stable difference`，不越过 evidence boundary。
- 原始/完整 outputs 只写 `VERUS_SKILL_RUN_ROOT`；repo 仅保留 compact plan、tracker、reviewed summary、contract 和 pointers。
