# Bounded implementation plan

## Selected route and authority

User requests a first extensible selection implementation and native SkillOpt card
generation, with two questions/eight traces analyzed in one batch. Assumption,
asked asynchronously: each question has one original plus three hint continuations.
Three checkpoints per question remains fixed. No paid experiment authorized by
this implementation pass. Dev-tier integration evidence, not main/test utility.

## Minimal code map and checks

1. New selector module: interchangeable candidate providers/policy version; shared
   eligibility, deterministic ranking, compile-episode deduplication and3-point
   fill. Verify synthetic plateau/helper/error/unknown/tie cases and all40 originals.
2. Offline preparation command: consume39 hash-bound reports, retain one failed
   original as context-only/no-reference. Generate selections and120 distinct fork
   job contracts under a fresh external run root; no actor/provider requests.
3. Grouped evidence adapter: per-task original+three completed hint continuations,
   full lossless trace data, distinct namespaces and prefix/suffix reconstruction.
   Validate branch seed/preservation identity, actual outcomes and checkpoint/hint
   association. Preserve failures, count two source tasks, not eight samples.
4. Native card update: call pinned SkillOpt Reflect with minibatch_size=2 and custom
   card output, not the independent extractor. Translate the card response to an
   internal no-edit payload required by native plumbing, then a card-bank sink.
   No generic skill edits/application or secondary model-based ranking. Native
   baseline path unchanged. Audit coverage of every trace, card labels/privacy/
   references, exact dedup only, and scoped transport restoration on errors.
5. Connect campaign selection/three branch contracts/native card batch path while
   keeping require_design_review paid gates closed. Fork context rehydration must
   use only the visible prefix, not final answers or future observations. It is
   not claimed to be an exact live Codex process/session restoration.

## Acceptance and stop

Minimum: executable modules, native Reflect mocked-provider integration and
regression tests. Solid: offline40-task selection produces exactly3 each, explicit
fallback reasons and deterministic hashes; two grouped tasks deliver all8 trace
records in one native model call and output auditable cards. No silent context
truncation; oversized full batches fail admission instead of silently splitting.
Maximum/causal value: future real forks/cards and leakage-safe600s evaluation;
not launched here. No significance test on implementation checks.

All generated outputs are external; raw/sealed originals and prior runs read-only.
No broad abstractions, no changes to unrelated dirty files or upstream checkout.
Artifact-specific experiment/science interfaces are unavailable; ordinary local
execution plus canonical research memory is the documented fallback. Update
CURRENT and index, report assumptions/limits/next action at closeout.
