# Train40 initial budget and failure audit

## Question

Why did the historical initial-skill training rollout solve only 23/40, was
the actor DeepSeek V4 Pro, and would raising the budget justify a fresh run?

## Evidence and method

Read the historical epoch contract, the August 19 non-timeout failure audit,
the current forty-task proposal, and all forty canonical initial-rollout
`result.json` files. Inspected the first twelve lines of original/candidate
copies for the seventeen failures to check the builtin-macro import change.
No verifier, model, external API or GPU job was run.

External run basename:
`codex-pro-fixed80-e1-600s-20260817-1916` under the SkillOpt run root.
Exact relative evidence: `steps/step_0001/rollout/predictions/<task_id>/result.json`,
`run_manifest.json`, `workspace/input.rs`, and `workspace/candidate.rs`.
This host has forty readable result records; the earlier readiness audit's
three-original observation was host-specific. Full trajectory integrity and
new-run readiness have not been established by this result-file inspection.

## Findings

- All forty results name `deepseek-v4-pro` and actor reasoning `max`.
- Frozen actor task timeout was 600 seconds; initial skill was the same
  838-byte seed. GPT-5.6 Sol was the separate optimizer, not the actor.
- Outcomes: 23 solved, 15 unsolved timeouts, two normal unsolved terminations.
- Eight unsolved IR inputs contain
  `extern crate verus_builtin_macros as builtin_macros;`.
- Three retain the alias and end with missing-crate diagnostics and preservation
  passing. All three time out.
- Five remove the alias and fail preservation. Four of these pass Verus; the
  fifth also fails Verus. Three time out and two terminate normally.
- The other nine unsolved cases time out. More time may help these cases, but
  the audit does not establish that all are recoverable.

This corroborates the old toolchain/preservation incompatibility diagnosis.
Do not interpret 23/40 as a clean capability ceiling or attribute all failures
to insufficient token budget. Task wall time, context capacity, reasoning effort,
per-request output limit and cumulative output budget are distinct controls.
The request ceiling must be effective on the actual provider payload before
it can be treated as a cost or truncation guarantee.

## Recommendation and limits

Follow-up clarification prompted by the user: this is a historical defect,
not evidence that current code still needs the same repair. The August 20 setup
record documents installation of the official September Verus comparator;
the disputed references then verified and inputs reached intended proof errors.
The August 22 alignment report documents the September 12 formal release pin,
version-sensitive candidate checks and the pre-inference identity gate, which
is present in `verus_release.py`, `test_eval.py`, and `skill_validation.py`.
The cited 23/40 result was not regenerated by those changes. The recommendation
means confirming the repaired setup before a new run, not implementing the
same fix again. Sources: the August 19 setup experiment entry and
`skillopt-verusage/refine-logs/VSKILL_0822_TRACE2SKILL_ALIGNMENT.md`.

First confirm compatible Verus/Lynette and unchanged-source behavior on the
alias-affected tasks. Preserve the frozen dataset; do not delete imports in
benchmark inputs to manufacture passes. Then use a fresh common original40
run for all learning conditions, preserving the initial skill and actor while
raising the task wall-time proposal from 600 to 1,200 seconds. Small training-only
engineering checks may precede it. Higher limits remain a proposal, not an
approved launch or a promise of forty solved source tasks.

Log actual completed requests, effective output limits, input/cache/output
tokens, wall time, failures and total generation cost. Budget changes in training
must be shared by SkillOpt and augmentation; downstream evaluation uses its own
common frozen budget. Keep all forty original trajectories, including failures;
record the actual hint-eligible count instead of replacing difficult sources.
No configuration or active experiment was changed in this audit.

## Safety

Historical result/source copies were read without modification. No sealed/test
data, credentials or full raw trace was read or copied into this note. No paid
inference, GPU use, rerun or export occurred. Only compact repo-local memory
was updated and its index regenerated.
