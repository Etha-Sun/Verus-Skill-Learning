# Hint v1/v2 内容核对：数学完整度、具体程度与teacher开销

## 结论

**本轮不支持“v2普遍补齐了v1没有的数学计划”。** AL两版数学链基本相同；IR v1本来已给详细双向见证及兼容提醒；AC若干点的v2把操作和中间谓词联系写得更具体，但v1也已覆盖核心义务。最值得研究的是具体化／修复范围组织，而非笼统称v2数学更完整。

**“hint agent做得更多”若指输出token，则确实如此：** v2的teacher输出和reasoning合计增加；但这包含兼容证据分析、JSON证据字段等，不能等同于新增数学思考，更不能等同于actor实际获得了更多有用信息。reasoning token属于teacher内部用量，不发给actor；只有hint_text发给actor。

## 审计纠错与输入核验

此前AC v1 CP4被判为只讲implies、缺下一层见证；AC v2 CP5被判为未提醒请求侧。**这两项旧判断错误：多段hint的第二段被早期摘要遗漏。** 本次直接读取全部hint.json，并逐字核对38个hint_text与actor的hint.txt、prompt.txt，均一致，actor实际收到完整hint，未被截断。相关本地详细报告、合并报告、结构化审计和仓库发布副本已纠正；原始hint／trace未改。本次提交同步修正发布报告。

- AC v1 CP4第二段原文包含：`The next expected obstacle is the existential goal for tla_exists`，随后要求响应或请求见证。
- AC v2 CP5第二段原文包含：`The same witness-naming approach will likely be needed later for q_mid.entails(tla_exists(p_req))`。

这改变的是hint覆盖评价，不改变原有成功率、代码路径或用量。不能再将AC CP4的版本差异解释成只有v2才提醒第二层。

## 对归因的更新

1. 现有证据支持：AC部分提示在已有正确数学框架下更具体，AL部分提示更明确修复范围和兼容边界。这可能帮助actor减少额外搜索／错误实现。
2. 现有证据不支持：v1普遍缺数学步骤、v2普遍补齐；或v2一律限制更紧。AL CP4的v2反而允许宏和显式外延性两种实现。
3. 仍有反例：AC CP3的v2多了明确implies指导却泛型化失败；AL CP2两版都完整、都一次修改，token仍有差别。执行采样与实现选择不能被忽略。
4. teacher reasoning增加说明用量增加，不证明质量增加；内部reasoning未作逐句正确性审计。现阶段可说“teacher多花生成成本，actor多数点少花生成成本，数学内容大体一致、部分表达更具体”，不宜说“teacher替actor完成更多数学，所以省token”已得到因果验证。

本次只核对hint内容和现有usage。首次双通过前成本、actor搜索／规划／结束说明的token分解仍是后续独立审计，未在此报告中冒称完成。没有新增API调用，也没有按成功结果重生成hint。
